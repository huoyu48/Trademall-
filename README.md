# OrderFlow

> 一个面向实习简历的**多租户订单履约平台**：覆盖高并发下单防超卖、订单状态机、异步可靠通知（重试 + 死信兜底）、多租户数据隔离，前端配套 Vue3 数据看板。

这个项目不是"能跑就行"的 demo，它刻意把几个面试常考的点做扎实了：多租户隔离、高并发防超卖、状态机、消息队列的异步解耦与死信兜底。

## 技术亮点

每一项是简历上可以写、面试官可以追问的点，点开都能讲出实现细节：

- **多租户数据隔离**
  基于 MyBatis-Plus 的多租户拦截器做 SQL 拦截，所有查询自动拼上 `tenant_id`。租户 A 和租户 B 的数据在代码层无感知地彻底隔离，不用在每个 SQL 里手写条件。

- **高并发防超卖**
  下单时用 Redis 分布式锁锁住"商品维度"，库存扣减和订单创建放在同一事务边界内。锁保证不会两个请求同时扣同一件商品，事务保证"扣库存"和"建订单"要么都成、要么都回滚。

- **订单状态机**
  订单生命周期是 `CREATED → CONFIRMED → SHIPPED → COMPLETED`，以及终态 `CANCELLED`。状态只能按允许的边流转，非法跳转会被拒绝，流转过程可审计。

- **异步解耦 + 可靠性兜底（重点）**
  下单成功后发 RabbitMQ 事件，通知服务异步消费，不在主链路里等。消费失败时重试 **3 次**，仍失败则**拒收进 DLQ 死信队列**，由死信消费者归档到 `notification_failure` 表。好处是：毒消息既不丢、也不阻塞正常队列。

- **订单超时自动取消**
  `@EnableScheduling` 定时任务扫描"已创建但未支付"的订单，自动取消并回补库存，避免占库存不放。

- **可观测性**
  有真实的 `/api/health` 端点，逐个探活 MySQL / Redis / RabbitMQ；通知与死信都有结构化落库，方便排查。

## 快速开始

```bash
make run     # 一键启动，然后浏览器打开 http://localhost:8088
make stop    # 用完关掉，释放资源
```

默认账号 `admin-a / admin123`（租户 A）、`admin-b / admin123`（租户 B）。详细启动方式、端口约定、环境要求见 [RUN.md](docs/RUN.md)。
