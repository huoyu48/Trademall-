# 提交改动说明

本文件用业务语言记录重要提交做了什么，便于在 GitHub 上快速了解项目演进。

> Git 提交一旦推送，直接补充其说明会改写历史并需要强制推送。为避免影响已有提交，统一在这里按提交号补充说明；后续功能提交也应同步追加一条记录。

## 2026-08-19

### 本次提交 · 商户支付履约与顾客退款售后

- 商家订单详情和列表新增脱敏支付信息：支付方式、支付流水号、支付金额、支付时间和支付状态，便于客服核对付款，且不暴露付款码或回调令牌。
- 已付款订单不再允许直接取消；商家只能确认履约、发货或进入退款流程，避免出现“订单已取消但款项未退”的状态错误。
- 顾客可对自己的已付款、待确认、已发货或已完成订单申请退款；商家在退款列表确认或拒绝。确认后订单和支付流水同步为“已退款”，拒绝后恢复退款前的原订单状态。
- 退款流程补充订单归属校验、原状态保存和条件状态更新；未发货退款会释放预占库存，已发货退款不自动回补，避免已寄出商品被再次出售。
- 商家仪表盘的“今日已付款订单”和销售额只统计已付款及之后的订单状态，排除待付款订单造成的虚高。

### [`15b6a73`](../commit/15b6a73) · 模拟扫码付款替换支付宝

- 下线商城中的支付宝沙箱调用、密钥配置与回调接口，避免支付功能依赖外部沙箱稳定性。
- 购物车和“我的订单”改为“模拟扫码付款”：电脑展示二维码，手机打开项目自己的模拟收银台后确认付款。
- 支付成功后由服务端把订单从“待付款”更新为“已付款，待商家确认”；保留支付流水、付款码过期、重复确认防护、取消订单和超时关闭。
- 新增付款码数据库字段与公开收银台页面；历史渠道未完成的流水会关闭，防止同一订单出现两个付款入口。

### [`7e690ad`](../commit/7e690ad) · 支付宝沙箱支付流程

- 首次补齐了支付能力的完整链路：待付款订单、独立支付流水、二维码展示、支付状态轮询、顾客取消和超时关单。
- 支付宝沙箱返回结果经服务端验签、金额核对和条件更新后，订单才会变为已付款。
- 该实现随后因沙箱环境不稳定被上面的模拟扫码付款替换，但订单状态机、支付流水和关单设计被保留并复用。

### [`a0dd80f`](../commit/a0dd80f) · 商城下单与库存流程优化

- 顾客购物车按店铺拆分下单，结算页与订单页展示店铺名称、店铺优惠和优惠后的应付金额。
- 满减按“每满门槛减一次”计算，例如每满 500 减 80，金额达到 3499 时可多次减免。
- 商品库存调整不再强制填写原因；商家后台仪表盘的待处理订单、低库存商品可以跳转查看明细。
- 店铺名称改为全平台唯一；商家新增/编辑商品后可正确出现在顾客商城首页。

## 2026-08-18

### [`acabc32`](../commit/acabc32) · 顾客与商家实时咨询

- 顾客可从商品或订单入口联系对应商家，商家后台可查看客户咨询会话。
- 会话与消息先写入数据库，再通过 WebSocket/STOMP 推送；离线后仍可查看历史记录和未读消息。
- 服务端按顾客身份、商品归属和商家租户校验会话权限，避免跨商家查看消息。

### [`4b5c373`](../commit/4b5c373) · 可靠下单投递与验证

- 下单事务中写入 Outbox 事件，后台再投递到 RabbitMQ，降低“订单已创建但通知丢失”的风险。
- 消费端按事件 ID 去重，失败会重试并进入死信队列，通知记录也具备幂等保护。
- 增加并发下单脚本、自动化测试和 CI 校验，便于验证库存守恒、租户隔离与消息投递。

### [`60caaee`](../commit/60caaee) · 顾客注册

- 统一登录页增加顾客注册入口，顾客可自行填写账号、密码、昵称和手机号。
- 服务端校验重复账号、两次密码一致性和输入格式；注册成功后直接返回顾客登录令牌。
- 注册顾客归入商城默认租户，前端自动保存顾客登录态并进入商城。
